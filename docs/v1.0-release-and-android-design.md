# YHCT Social v1.0 — Release & Android Preparation Design

## Release target

- Canonical web app: `https://yhct-social.vercel.app`
- Web stack: Next.js 16 + React 19 + Firebase Auth/Firestore/Storage + Vercel.
- Release version: `1.0.0`, Git tag/release: `v1.0.0` only after final verification gates pass.
- Firebase project is fixed to `yhct-social-260902-42a4`.
- Existing private migration bundle remains outside the public repository.

## v1.0 acceptance gates

1. CI: unit/contract tests, TypeScript, lint, production build all pass.
2. Firebase: Firestore rules/indexes and Storage rules deploy successfully.
3. Migration: private Drive bundle passes checksum + dry-run + import; Firestore post-import counts must be exactly 159 migration members and 2 activities.
4. Web production: Vercel production deployment succeeds and canonical URL returns HTTP 2xx.
5. Security: migration member staging is moderator/admin readable only and client-write denied; activities are public only when published and client-write denied.
6. Release metadata and handover documentation are committed before tag `v1.0.0`.

## Modern app-web baseline

Add a web app manifest with Vietnamese product metadata, standalone display mode, canonical start URL `/`, and install-oriented metadata. This keeps the web app as the single source of truth and prepares the project for Android packaging without duplicating business logic.

## Android preparation

The Android deliverable for this cycle is a **preparatory internal APK**, not the Play Store release artifact. It is generated from a pinned Capacitor 8.5.1 shell that opens the canonical HTTPS web app.

- App name: `YHCT Social`
- Android application id: `vn.hiu.yhctsocial`
- Canonical remote origin: `https://yhct-social.vercel.app`
- Cleartext traffic: disabled.
- Capacitor packages: `@capacitor/core`, `@capacitor/android`, `@capacitor/cli` pinned to `8.5.1`.
- CI output: debug-signed APK artifact + SHA-256 checksum.
- No signing keystore is committed to Git. Release/AAB signing is intentionally deferred to the next mobile update when a protected long-lived keystore is provisioned.

### Authentication limitation of the preparatory APK

Firebase email/password remains suitable for internal shell testing. Google OAuth inside embedded WebViews can be restricted by Google; therefore native Google Sign-In is explicitly a future Android enhancement and is not a v1.0 web acceptance blocker. The production web app remains the v1.0 canonical product.

## Update strategy

The web application stays authoritative. Web releases update independently through Vercel. Future Android versions may add native Capacitor plugins and native authentication while keeping the same Firebase data model and domain services. This avoids maintaining two application backends or two independent business-logic codebases.
